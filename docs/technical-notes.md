# 구현 버전과 검증 범위

[프로젝트 소개](../README.md) · [개발 과정과 문제 해결](development-notes.md)

프로젝트 소개는 공개 GitHub 소스와 실차 개발을 정리한 상세 기록을 함께 사용합니다. 공개 소스는 [2025년 9월 20일 커밋](https://github.com/Khusla/HLFMA_2025/tree/48406564072bd34c5d223b7e9fb8b05a2381fa11)을 기준으로 읽었습니다. 상세 기록은 여러 실차·시뮬레이션 작업공간을 분석한 자료이며, 일부 구현은 공개 커밋과 다릅니다. 이번 포트폴리오 정리에서 장비를 연결해 빌드하거나 주행을 재현하지는 않았습니다.

## 공개 코드와 보관 기록의 차이

| 항목 | 공개 커밋에서 확인 | 상세 기록의 실차 보관본 설명 |
|---|---|---|
| 초기 방향 보정 | GPS 변위 1 m, 직진 경로, EKF yaw 오프셋 | 같은 원리에 `correctioning` 상태 전달과 보정 중 구동값 변경이 연결됨 |
| 경로 | `/gps/centerline1`을 받아 전방 경로 계산 | 여러 일반·대안 경로, 말단 대기, 전진·후진 전환 |
| 카메라 | YOLOv5 노드와 `detections_v5` | YOLOv8 API 기반 노드와 `detections_v8`; 실제 사용 가중치 계열은 별도 확인 필요 |
| 신호등 | 상태 발행·구독·저장. 활성 구동 명령에 적용하는 분기 없음 | 지정 위치 반경 안에서 Red·Yellow 상태에 정지 명령 적용 |
| LiDAR 전방 검출 | 거리 상한 2 m, 연속 검출 5회, 0° 경계 구간 처리 점검 필요 | 거리 상한 3 m, 연속 검출 3회, 0° 경계 분리 판정 및 좌·우 검출기 설명 |
| 하위 제어 | 시리얼 명령 송신 | 별도 Arduino 펌웨어의 구동 PWM·포텐시오미터 조향 피드백 설명 |
| 시뮬레이션 | 현재 공개 트리의 주된 범위가 아님 | Gazebo 차량 모델, 가상 센서, 브리지·위치 추정 설정 분석 |

표의 수치는 **설정·조건·명령값**입니다. 폴더명이나 기록 시각만으로 최종 대회 사용 버전과 변경 순서를 확정하지 않습니다. 특히 공개 커밋의 누락 기능이나 실행 점검 항목을 프로젝트 전체의 미구현 상태로 일반화하지 않습니다.

공개 `PathPlanningResult.msg`에도 `correctioning`과 `reverse` 필드는 정의되어 있습니다. 필드가 있다는 사실과 해당 노드가 상태를 발행·처리한다는 사실은 구분합니다.

## 공통 구조를 읽는 기준

- 실차 중심 EKF 설정은 오도메트리 속도와 IMU 방향·회전 정보를 입력으로 사용합니다. 경로계획은 GNSS 변환 위치와 EKF 방향을 별도로 받습니다. 오도메트리 입력 코드의 존재만으로 실차 엔코더 운용이 검증된 것은 아닙니다.
- 초기 yaw 오프셋은 경로계획기와 별도 디버그 출력에 적용합니다. 원시 IMU·EKF 상태·navsat·TF 전체를 교정하는 절차가 아닙니다.
- 경로 제어는 목표점 방향에 따른 단계 조향입니다. 전방 경로점 선택과 곡률식 기반 Pure Pursuit 제어기는 구분합니다.
- LiDAR 정지는 지정 구간의 세션당 한 번 발동하는 상태 로직입니다. 전 구간 상시 충돌회피로 설명하지 않습니다.
- 명령값과 실제 속도, 설정 주기와 측정 FPS, 경로점 연결 길이와 실제 주행거리를 구분합니다.

## 근거가 뒷받침하는 범위

| 근거 | 확인할 수 있는 내용 | 그 근거만으로 확정하지 않는 내용 |
|---|---|---|
| 프로젝트·수상 기록 | 차량 개조 경험, 초기 방향 문제 해결 경험, 장려상 수상 | 기능별 실주행 성공률 |
| 공개 소스 검토 | 조건 분기, 토픽·메시지, 계산식, 설정값 | 장비가 연결된 최종 실행 결과 |
| 보관 자료의 상세 분석 | 실차 확장·Arduino·시뮬레이션 구성과 버전 차이 | 해당 구현 모두가 대회에서 사용되었다는 주장 |
| 저장 경로 분석 기록 | 좌표점 수, 형상, 파일 간 공통점, 형식 차이 | 실제 추종 궤적·완주거리·차량 위치 정확도 |
| 점검용 노드와 로그 코드 | 관측할 수 있도록 구성한 데이터 | 실제로 보관된 실험 로그나 시험 통과 결과 |

## 공개 커밋을 재현할 때 확인할 구성

아래는 링크한 공개 커밋의 정적 점검 사항입니다. 대회 당시 실제로 발생한 장애 목록이나 보관본 전체에 적용되는 결론이 아닙니다.

| 항목 | 공개 커밋의 상태 | 필요한 확인 |
|---|---|---|
| 환경 | 설치 스크립트가 ROS 2 Humble 패키지를 사용 | 실제 운영체제·드라이버·Python 패키지 조합 |
| LiDAR 발행 | `LPFL` 이름을 사용하지만 대응 별칭 정의가 없음 | import 및 모듈 참조 수정 후 장비 검증 |
| LiDAR 각도 범위 | 340°~20° 설정과 index 교환 로직 | 0°를 지나는 검출 구간 처리 |
| 경로 launch | 노드 1~5를 선언하나 노드 2~5 및 해당 CSV가 현재 트리에 없음 | 실제 사용하는 노드·경로로 실행 구성 정리 |
| LiDAR launch 설치 | 패키지 `setup.py`에 launch 파일 설치 항목 없음 | 설치 후 launch 탐색 경로 |
| 시리얼 장치 | 오도메트리 수신·명령 송신 기본 장치는 같고 통신 속도는 다름 | 실제 장치 배치·통신 속도·접근 방식 |
| 통합 실행 | 위치 관련 launch와 개별 노드가 분리됨 | 최종 사용 노드 집합과 시작 순서 |
| 데이터 경로 | 개발 환경의 절대 경로가 포함됨 | CSV·로그·모델 경로 설정 |

초기 보정에는 GPS 품질·위치 점프·EKF yaw 수신 여부·입력 시각의 정합성을 별도로 검증할 여지가 있습니다. 이러한 후속 점검을 이미 수행한 개선 결과로 소개하지는 않습니다.
