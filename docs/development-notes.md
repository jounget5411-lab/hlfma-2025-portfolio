차량 개조와 센서 통합을 시작으로, 초기 방향 보정·경로 추종·미션 처리·하위 제어를 연결한 개발 과정입니다.

## 1. 초기 방향 문제 · 1 m 이동을 초기화 절차로 만들기

### 위치와 방향의 기준을 함께 맞추기

유아용 전동차를 개조하고 Ubuntu 노트북과 센서를 연결한 뒤, 지도 경로와 차량 방향의 기준을 통합했습니다. 차량 기준 목표 경로를 만들려면 현재 위치와 지도에서 차량이 향하는 방향이 모두 필요합니다. yaw에 고정된 오차가 남으면 경로점의 상대 방향이 달라져 조향 판단에 영향을 주었습니다.

### 실제 이동으로 방향 오프셋 계산

GPS 위치와 경로가 준비되면 경로계획기가 시작 위치를 저장합니다. 시작점과 현재 GPS 위치의 직선 변위가 1 m 미만인 동안 `(0, 0) → (0, 1)`의 차량 정면 경로를 내보냅니다. 기준을 넘으면 이동벡터로 방향을 구하고, EKF 방향과의 차이를 한 번 저장합니다.

```text
이동 방향     = atan2(y₁ − y₀, x₁ − x₀)
yaw 오프셋    = 이동 방향 − 보정 시점의 EKF yaw
이후 보정 yaw = 현재 EKF yaw + 고정한 오프셋
```

공개 코드의 `_imu_yaw`는 `/odometry/filtered`의 quaternion에서 읽은 값입니다. 이 EKF 방향에 오프셋을 적용해, 실제 이동 방향을 기준으로 경로를 차량 좌표계로 변환했습니다.

[초기 방향 보정 코드](https://github.com/Khusla/HLFMA_2025/blob/48406564072bd34c5d223b7e9fb8b05a2381fa11/src/decision_making_pkg/decision_making_pkg/path_planner_node.py#L219)

### 초기화 상태를 구동 계층까지 전달

실차 개발 보관본에서는 `correctioning` 상태를 경로 메시지로 전달하도록 확장했습니다. 초기 직진 중에는 구동 명령을 기본값 120에서 80으로 낮추고, 방향 정렬이 끝나면 일반 추종으로 전환합니다. 방향 계산과 차량 동작을 같은 초기화 상태로 연결한 구성입니다.

짧은 전진 동작을 초기화 절차에 포함함으로써 초기 방향 문제를 해결했습니다. 보정 yaw는 이후 경로 계산과 시각화에 함께 사용해 일관된 방향 기준을 유지했습니다.

## 2. 좌표 통합 · 지도 경로에서 조향 부호까지 연결

### 경로와 현재 위치의 변환 기준 공유

CSV의 위도·경도 경로를 미터 단위의 평면 좌표로 변환했습니다. GNSS 위치 변환에 사용하는 `navsat_transform_node`의 `FromLL` 서비스를 경로에도 적용해 좌표 기준을 맞췄습니다. 변환한 점의 누적 길이를 구한 뒤, 기본 간격 0.30 m로 x·y를 선형 보간해 경로를 재샘플링합니다.

[경로 로더](https://github.com/Khusla/HLFMA_2025/blob/48406564072bd34c5d223b7e9fb8b05a2381fa11/src/gps_path/gps_path/test_path_node1.py)

### 차량 기준 축과 명령의 부호 연결

현재 위치를 뺀 경로점의 상대변위를 `(dx, dy)`, 보정 방향을 `ψ`라고 하면 차량 좌표로의 변환은 다음과 같습니다.

```text
x_local = sin(ψ) × dx − cos(ψ) × dy
y_local = cos(ψ) × dx + sin(ψ) × dy
```

경로 메시지의 축은 **오른쪽 +x, 전방 +y**로 정의했습니다. 지도 +x 방향을 보고 있을 때 전방 점 `(dx > 0, dy = 0)`은 차량 좌표 `(0, +y)`로 바뀌고, 왼쪽 점은 음의 local x가 됩니다. 이 규약에 맞춰 제어 노드가 `atan2(x_target, y_target)`로 상대 목표 방향을 계산합니다.

상위 조향은 좌우 1~5단계와 중앙 0으로 나뉩니다. Arduino 제어에서는 각 단계를 포텐시오미터 목표값으로 매핑하고, 현재 조향 위치와의 오차에 따라 모터를 구동했습니다. 지도 좌표, 차량 기준 축, 조향 단계, 하위 구동 부호를 이어 차량의 실제 움직임으로 연결했습니다.

## 3. 디버깅 · 계산한 방향과 목표 경로 함께 관측

경로계획기가 사용하는 보정 yaw를 `/path_planner/yaw_corrected`로 발행했습니다. 시각화 노드는 GPS 위치와 보정 방향을 받아 현재 자세, 방향 화살표, 전방 경로를 구성합니다. 제어 판단에 사용한 방향과 경로를 같은 화면에서 살펴볼 수 있도록 만들었습니다.

| 관측 출력 | 내용 |
|---|---|
| `/pp/current_pose` | 현재 위치와 보정 방향 |
| `/pp/current_heading` | 차량이 바라보는 방향의 화살표 |
| `/pp/preview_path` | 차량 기준 경로를 지도 주변 좌표로 변환한 미리보기 |
| 경로계획 CSV 로그 | 경유점 인덱스, 횡편차, 방향 오차, 목표점 거리, 복구 이벤트 |

[시각화 코드](https://github.com/Khusla/HLFMA_2025/blob/48406564072bd34c5d223b7e9fb8b05a2381fa11/src/debug_pkg/debug_pkg/gps_path_visualizer_node.py) · [경로계획 로그](https://github.com/Khusla/HLFMA_2025/blob/48406564072bd34c5d223b7e9fb8b05a2381fa11/src/decision_making_pkg/decision_making_pkg/path_planner_node.py#L123)

## 4. 실차 미션과 하위 제어 확장

실차 개발 보관본에서는 기본 경로 추종을 미션별 상태 전환과 하위 제어로 확장했습니다. 공개 코드와의 구성별 대응은 [구현 구성과 설정](technical-notes.md)에 정리했습니다.

| 개발 과제 | 구현 |
|---|---|
| 구간별 경로와 진행 방향 관리 | 일반·대안 경로를 나누고, 경로 말단에서 대기·경로 선택·전진/후진 전환 |
| 신호등 인식과 위치 조건 연결 | 지정 신호등 지점의 반경 안에서 빨강·노랑 검출 시 구동 명령을 0으로 변경 |
| 후진 전환 시 명령 변화 조절 | 직전 목표 유지 시간, 조향 단계 변화 제한, 별도 후진 구동값 적용 |
| 조향 단계를 기구 위치로 전달 | 포텐시오미터 목표와 현재값의 오차에 따라 Arduino가 조향 모터 구동 |
| 가상 환경에서 센서와 제어 흐름 구성 | Gazebo HENES 모델, 가상 GNSS, ROS 센서·명령 브리지, 경로 미리보기 연결 |

## 프로젝트 성과

HENES-T870 차량 개조부터 센서 통합, 초기 방향 보정, 경로계획, 조향·구동 명령, Arduino 하위 제어까지 자율주행 시스템의 흐름을 연결했습니다. 실제 이동벡터를 이용해 초기 방향 문제를 해결하고, 미션별 상태 전환과 시각화 도구를 개발했습니다. **HL FMA 2025 자율주행 경진대회에서 장려상을 수상했습니다.**
